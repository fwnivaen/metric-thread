# Contributing

Start with the README's development commands. Use fictional fixtures and describe the business input, expected output and evidence when reporting a bug.

Useful contributions include additional numeric notations with exact validation, source adapters that produce the existing bundle contract, and explicit catalog migrations. Keep model-specific behavior behind the extraction adapter.

For a behavior change, add a focused test showing the failure or contract edge. Run tests, lint, formatting and the offline demo before a pull request. Do not add private customer messages or credentials to issues, fixtures or commits.
